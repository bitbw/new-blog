# 博客与 Notes 内容整理方案

## 目标

把站点从“资料都放在一起”整理成两种清晰的阅读入口：

- **Notes**：长期可查的知识库，解决“我想快速找到一个问题的答案”。
- **Writing**：项目实践和技术文章，解决“我想理解一个完整过程或观点”。

本方案优先改善导航和入口，不一次性移动 135 篇历史文档，也不删除旧内容，避免无谓地改变已有 URL。

## 当前问题

- `docs/` 约有 135 篇文档，前端相关内容约占大多数，自动目录直接暴露历史文件夹结构。
- `blog/` 的新文章已经形成 AI、Skill 和项目实践方向，但还缺少系列化入口。
- 旧内容中包含 Vue 2、Webpack 4、Hexo、New Bing 和旧版 Electron 等历史技术，和当前推荐内容混在一起。
- 同一主题存在多篇“常见问题汇总”，用户不容易判断应该先看哪一篇。
- 目录和文件名存在中英文大小写、空格和命名风格不一致的问题。

## 内容边界

### Notes

收录稳定、可反复查询的内容：

- 前端基础、框架和工程化
- Git、GitHub、Docker、CI/CD
- Windows、Linux、macOS
- 网络、数据库、算法和常用工具

### Writing

收录有背景、过程和结论的内容：

- AI Agent、Codex、Claude Code、MCP
- Skill 和自动化工具开发
- 个人项目拆解
- 公司项目中可以公开的工程经验
- 技术选择、方法论和阶段性思考

## 目标目录

Notes 一级目录保持现有文件路径不变，只统一展示为以下分类：

```text
Notes
├── 前端开发
├── AI 与开发工具
├── 工程与交付
├── 操作系统
├── 网络与接口
├── 数据库
└── 基础与算法
```

Writing 保持现有 5 个分类：

```text
AI 与 Agent
自动化与效率
项目实践
前端与工程
工具与基础知识
```

重点系列暂按文章标签和分类组织，不新增复杂 CMS：

- AI 编程与 Agent
- DeepSeek Harness / DSH
- Skill 与自动化
- 个人项目实践

## 分阶段执行

### 第一阶段：入口和目录

- 重写 Notes 介绍页，说明内容边界和推荐入口。
- 使用 `_category_.json` 统一一级目录名称、顺序和描述。
- 增加历史内容说明，不立即搬迁或删除旧文档。
- 保持现有中文、英文和文章 URL。
- 为新增 Writing 文章补充截断标记，避免列表页过长。

### 第二阶段：文章系列

- 给 AI、Skill、项目文章补充系列入口和互相链接。
- 统一标题、标签和摘要风格。
- 首页只展示精选文章，不手工维护过多固定链接。

### 第三阶段：旧文档收敛

- 合并重复的 Vue、npm、Webpack、Electron FAQ。
- 为 Vue 2、Webpack 4、Hexo、New Bing 等内容标记 `legacy` 或迁移到 Archive。
- 需要移动文件时保留旧 URL 或添加重定向。

## 当前落地状态

第二阶段和第三阶段已完成第一版：

- 已新增 [Writing 系列索引](./Writing 系列索引.md)。
- 已新增 Vue、npm、Webpack、Electron 统一入口页。
- 已为明显过时的 Vue 2、旧版 Vue CLI、Webpack 4、早期 Yarn/npm、旧版 Electron 和 New Bing 笔记增加 status: legacy。
- 原文章和 URL 均保留，后续合并以入口收敛为主。

## 本次落地范围

本次已完成第一阶段，并执行第二、第三阶段的第一版整理，完成以下验收：

1. Notes 介绍页能解释两套内容的区别。
2. Notes 一级目录显示为统一分类。
3. 历史内容有明确说明，但原文件仍可访问。
4. Blog 新文章列表不会直接展示全文。
5. Writing 有按主题和项目划分的系列索引。
6. Vue、npm、Webpack、Electron 有统一入口，旧文档仍保留原 URL。
7. 明显过时的笔记已增加 status: legacy。
8. `npm run typecheck` 和 `npm run build` 通过。
9. 中文 Notes、Writing 页面和移动端导航可以访问。

后续内容合并和归档，单独按主题分批处理，不与本次导航调整混在一起。
